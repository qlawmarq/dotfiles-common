# writing-japanese

抑えたいものは三つある。日本語として不自然な表現、不自然な構成、そして AI が書いたと分かる決まり文句と装飾である。
本体の規則はどの分野、どの長さの文章にも当てはまる。詳しい型は `references/` にあり、必要なときだけ読む。

## 0. 読者と文脈

誰が読み、読んだ後に何をするかを決めてから書く。短い返答でも省かない。
不自然な日本語の多くは、直前に読んだ英語の資料、コード、専門的なやりとりの語彙と語順が、そのまま日本語に流れ込んで生まれる。
内容が難しく文章が長いほど起きやすい。書く前に、読者がその文章だけを読む場面を思い浮かべ、文脈にあった語ではなく読者が知っている語で書く。
文体（です・ます／である）は、指定、既存の文書、会話の順に合わせ、一つの文章の中で混ぜない。

## 1. 不自然な表現を出さない

### 述語を字義どおりに読めるか試す

英語で比喩として定着した動詞（carry、open、live、drive、surface など）を日本語の対応語に移すと、日本語では比喩として定着していないため、字義どおりの動作に読める。
物事を主語にした他動詞の文（「データが〜を示す」「結果が〜を強いる」）も、意思のない物事が何かをしているように読める。
判定は二段で行う。

1. その述語を初めて見る読者が、字義どおりの動作を思い浮かべうるか。思い浮かべうるなら疑う。
2. 誰が（何が）、何を、どうするのかを具体的な語で言い直す。言い直せたら、言い直したほうを書く。

言い直せないなら、書き手が内容を決めきれていない。内容を決めてから書くか、削る。

- 「この問いは開かれている」→「この問いにはまだ答えが出ていない」
- 「雨が私たちに予定の変更を強いた」→「雨で予定を変えることになった」

### 英語の語をそのまま持ち込まない

英語の動詞をカタカナにして「する」「される」を付けた語は、読者の間で定着しているものだけ使う。定着していなければ、動作を日本語で書く。読者が自分自身なら、自分が日常で使っている語は定着している語として扱う。
その分野で慣用されている訳語があればそれを使い、意味の近い漢語を一般語の感覚で充てない。
英語の用語や識別子をそのまま書くのは、読者が後でそれを検索したり入力したりする場合に限る。

### 文を組み立てる

一つの文には一つのことを書く。目安として六十字を大きく超えたら分ける。
主語と述語を近づける。長い修飾語は前に、短い修飾語は修飾される語の直前に置く。
読点は、係り受けの切れ目と、そこで切らないと別の読み方ができる箇所に打つ。
「〜の〜の〜の」の連鎖、「〜の実施を行う」のような名詞化、受け身の連続、二重否定は、動詞で言い直すか文を分ける。
同じ文末（「〜ます。〜ます。〜ます。」）や同じ書き出しが三つ続いたら、一つは変える。

### 語を選ぶ

初めて出す用語は、中身を説明してから名前を渡す。一つの文で新しい用語を二つ以上出さない。
漢語を重ねた言い方（「〜の実現に向けた取り組みを推進する」）は、和語の動詞で言い直せないか試す。
「〜的」「〜性」「〜化」を付けて名詞を作る前に、普通の言い方で言えないか試す。
話し言葉の評価語（「効く」「刺さる」「筋がいい」）は、日記や親しい相手への文章以外では、何がどうなるのかを書く。

## 2. 構成を自然にする

一つの段落に一つの話題を置き、段落の最初の文でその話題が分かるようにする。
論は一方向に進める。結論、反論の処理、結論の言い直し、と往復しない。
用語は中身を説明してから名前を渡し、一度決めた呼び名を最後まで使う。
同じ組み立ての段落や節が三つ続いたら、一つは変える。
冒頭で「本稿では〜を扱う」と宣言せず、結びで本文の要約を繰り返さない。
見出しの付け方は文書の読まれ方で変える。探して読む文書は対象を指す名詞句、通して読む文書は結論の分かる句でもよい。すべてを同じ書式にそろえない。
汎用の型（背景、目的、まとめ）を先に当てず、読者がその文書を開いたときに順に抱く問いを骨格にする。

## 3. AI らしさを抑える

「重要なのは」「〜について見ていきます」「まとめると」「〜と言えるでしょう」「ポイントは三つあります」「〜に他なりません」「いかがでしたか」は、情報を増やさずに書いている感じだけを足す。
その語句を消して内容が減らないなら削る。強調したいなら理由や具体例を書く。
「AではなくB」の対比は、読者が本当に誤解していそうなときだけ使う。
根拠なく語尾をぼかさない。一方で、推測や未確認のことを断定に書き換えない。
太字は読み落とすと困る箇所に限り、箇条書きは項目が本当に並列なときに使う。装飾の詳細は `references/markdown.md` にある。

## 4. references の読み方

既定では本体だけで書く。次の表で当てはまる行をすべて拾い、その行のファイルだけを読む。どの行にも当てはまらなければ何も読まない。

| 条件 | 読むファイル |
| --- | --- |
| 難しい内容の長文を書く、または直前の文脈に英語の資料やコードが多い | `translationese.md`、`readability.md` |
| 見出しのある長い文章を書く、構成を直す | `structure.md`、`genres.md` |
| 推敲・診断をする | `translationese.md`、`readability.md`、`hollow-phrases.md` |
| 出力が Markdown で、見出し・箇条書き・表を使う | `markdown.md` |
| 読み物としての緩急を明示的に求められた | `rhythm.md` |
| 引数に `full` がある | すべて |

## 5. 操作ごとの進め方

- write: 読者を決めて書き、§6 の点検をする。
- revise: 問題のある箇所を特定し、直す価値のある箇所だけを直して点検する。問題のない文は一字も変えない。最後に何をなぜ変えたかを数行で伝える。全見出しの結論化や全箇条書きの地の文化のような一律の変換はしない。
- diagnose: 本文を書き換えない。次の形式で並べ、最後に全体の傾向を二、三文で書く。点数は付けない。

```markdown
1. 「（該当箇所をそのまま引用）」
   - 型: （例: 直訳の比喩、物事の主語、文が長い、決まり文句）
   - 理由: （読者にとって何が読みにくいか）
   - 修正案: 「（書き換えた文）」
```

## 6. 書いた後の点検

長い文章では、書いた本人は元の資料の語彙に慣れてしまっていて、不自然さに気づきにくい。
可能なら、元の資料を渡さずに出力だけを別のエージェントに読ませ、`references/translationese.md` と `references/readability.md` を基準に点検させる。それができないときは、出力だけを読み直す。

1. 字義どおりに読める動詞、意思を持つように振る舞う物事の主語、定着していないカタカナ動詞が残っていないか。
2. 六十字を大きく超える文、主語と述語が離れた文、「の」の連鎖、名詞化、受け身の連続がないか。
3. 決まり文句、数の宣言、太字の多用がないか。
4. 見出しのある文章では、見出しと各段落の最初の文だけを続けて読み、話が通るか。
5. このスキルの言葉や手順名（「読者を決める」「一律の変換」など）が本文に出ていないか。出ていれば内容の言葉で書き直す。
