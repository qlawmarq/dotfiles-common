# Markdown の使い方

出典: k16shikano「日本語技術文書の文章規範」（Unlicense）と coji/natural-japanese の writing-constitution.md（MIT）を再構成した。

チャット画面では太字や箇条書きが目に留まりやすい。
その感覚のまま文書を書くと、強調がどこにでもあってどこも目立たない文章になる。
Markdown の記法は、読者が構造を追う助けになるときだけ使う。

## 太字

- 一つの節に一箇所までにする。文章全体で数箇所しかなくても不足ではない。
- 読み落とすと誤解や失敗につながる箇所（否定、例外、注意）に使う。
- 文全体を太字にしない。段落ごとに太字を置かない。
- 目立たせたい内容は、短い一文で言い切る、段落の最初に置く、といった書き方でも目立たせられる。

## 箇条書き

- 項目が同じ種類で、互いに独立して並ぶとき（持ち物、選択肢、条件）に使う。
- 項目の間に「だから」「しかし」でつながる関係があるなら、文章で書く。箇条書きにすると、書き手が組み立てるべき関係を読者に推測させることになる。
  - 例:「・寝坊した ・電車を一本逃した ・会議に遅れた」→「寝坊して電車を一本逃し、会議に遅れた。」
- 一項目は一、二文にする。項目の中に段落を書かない。
- 入れ子は二段までにする。
- 見出しの直後に箇条書きだけが続く節は、項目の間の関係が隠れていないか疑う。
- 項目ごとに「ポイント:」のような太字のラベルを付けない。

## 番号付きリスト

順番に意味があるとき（手順、優先順位）だけ使う。

## 表

- 複数の対象を同じ軸で比べるときに使う。比べる軸がなければ、文章か箇条書きにする。
- セルに長い文を書かない。長くなるなら表をやめる。

## 見出し

- 画面一つで読み切れる短い文章には付けない。
- 階層を飛ばさない。子の見出しが一つしかない階層を作らない。

## コード表記、引用、記号

- コマンド、ファイル名、入力する文字列はコード表記にする。単に目立たせたい語には使わない。
- 引用ブロックは実際の引用に使う。注意書きや強調のためには使わない。
- 絵文字、矢印、感嘆符を装飾に使わない。

## Markdown が表示されない場所

メール、メッセージアプリ、プレーンテキストの入力欄に書くときは、記法を使わない。
記号がそのまま表示されて読みにくくなる。
