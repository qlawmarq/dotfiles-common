# 情報源の評価と検証

収集フェーズと評価フェーズで使う具体手法。「この情報源は信頼できるか」を、操作されにくい方法で判断するための技術。

## 目次
1. ラテラルリーディング（横読み）
2. SIFT法
3. 一次・二次・三次情報
4. Admiralty（NATO）信頼性グレード
5. デジタルコンテンツ（画像・動画）の検証

---

## 1. ラテラルリーディング（横読み）

**原則**: 知らないサイトに着いたら、そのページを**精読せず離れて**、別タブでその情報源と主張を調べる。

なぜ有効か: サイトの見た目・ロゴ・.orgドメイン・「About」ページ・参考文献の長さは、すべて作り手が**操作できる表面手がかり**。これらを内部から評価しても騙される。一方、第三者がその情報源について何と言っているかは作り手が操作できない。Stanford の研究（Wineburg & McGrew 2019）では、プロのファクトチェッカーはこの横読みで信頼性判定の正答率100%、歴史家50%、学生20%だった。日本ファクトチェックセンター（JFC）も同手法を採用。

**手順**:
1. そのサイトの主張を一旦保留する。
2. 別の検索で「[媒体名/著者名] とは」「[媒体名] 信頼性 / 批判 / 資金源」を調べる。
3. その情報源が**そのことを知る立場にあるか**、専門性と利害（誰が運営・出資しているか）を確認する。
4. **クリック自制（click restraint）**: 検索結果の最初のヒットを鵜呑みにせず、複数の結果を見てから開く。

## 2. SIFT法（Mike Caulfield）

オンライン情報を素早く評価する4つの動作。あらゆるコンテンツ（記事・投稿・画像・統計）に適用できる。

| 動作 | 内容 |
|------|------|
| **Stop** | 読む・共有する前に一旦止まる。この情報源とその評判を知っているか？ 深掘りの迷路に入ったら再び止まる。 |
| **Investigate the source** | 深く読む前に60秒、情報源の専門性と意図を調べる（=ラテラルリーディング）。 |
| **Find better coverage** | 問題のある1つの情報源を評価するより、その**主張について**他のより良い情報源が何と言っているか探す。「この情報源は信頼できるか」を「多数の独立ソースは何と言っているか」に置き換える。合意か論争中かが見える。 |
| **Trace to original** | 引用・画像・動画・統計を**元の文脈**まで遡る。ネット上のコンテンツは切り取り・再キャプション・改変されていることが多く、元の文脈で意味が変わる/逆転することがある。 |

## 3. 一次・二次・三次情報

| 種類 | 例 | 扱い方 |
|------|-----|--------|
| **一次** | 公式文書、原典、生の統計データ、当事者の発言・会見の全文、実験結果、一次資料、現地の目撃 | **主張の根拠として優先**。各解釈レイヤーは誤り・誇張・文脈欠落の入り込む場所。 |
| **二次** | 解説記事、分析、多くのニュース報道、事件を解釈する書籍 | 文脈把握に有用。だが一次情報で裏を取る。 |
| **三次** | 百科事典、教科書、Wikipedia、データベース | **一次/二次情報を見つける入口**、情報源の評判を調べる入口として使う。主張の最終根拠にはしない。 |

数値や発言を報告する前に、可能な限り一次情報（原典・全文・生データ）に当たり、誇張・誤引用・ミスリードな編集がないか確認する。

## 4. Admiralty（NATO）信頼性グレード

各情報に2軸のグレードを付ける。例：「B2」。2軸は**独立に**判定する（信頼できる情報源でも誤情報を流しうるため）。

**情報源の信頼性（A〜F）**
- **A** 完全に信頼できる
- **B** 通常は信頼できる
- **C** まあまあ信頼できる
- **D** 通常は信頼できない
- **E** 信頼できない
- **F** 信頼性を判断できない

**情報の確度（1〜6）**
- **1** 他の独立した複数ソースで確認済み
- **2** おそらく真実
- **3** 可能性として真実
- **4** 疑わしい
- **5** ありそうにない
- **6** 真偽を判断できない

**運用ルール**: 確度「1」は**独立した複数ソースで裏付けが取れた場合のみ**与える。情報源の信頼性が高い（A/B）ことは、内容が裏付けられていること（確度）の代わりにはならない。出典：NATO AJP-2.1。

## 5. デジタルコンテンツ（画像・動画）の検証

First Draft の「検証の5本柱」を各コンテンツについて独立に検証する：
1. **Provenance（出所）** — オリジナルか、コピー/編集版か。最古・原版を探す。
2. **Source（発信元）** — 誰が撮影/投稿したか。実績と視点は。
3. **Date（日付）** — 投稿日でなく、実際に作られた日時。
4. **Location（場所）** — どこで撮られたか（地物・標識・地図と照合）。
5. **Motivation（動機）** — なぜ作られ共有されたか。

**手法**:
- **逆画像検索**（Google画像, TinEye, Yandex, InVID-WeVerify）: 画像が以前どこに出たか探す。古い画像を新しい事件として使う最も多い手口を暴ける。
- **最古版を探す**: オリジナルが正しい文脈・日付・著者を持つ。下流のコピーはそれを失う/改変している。
- **メタデータは補助**: EXIFはSNSで除去されやすく偽造も容易。決定的証拠でなく補強材料として扱う。
