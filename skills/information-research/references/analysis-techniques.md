# 分析手法と不確実性の表現

分析フェーズ（フェーズ4）と報告フェーズ（フェーズ5）で使う構造的分析技術。確証バイアスを構造的に防ぎ、不確実性を正直に表現するためのもの。

## 目次
1. 競合仮説分析（ACH）
2. 重要前提のチェック（Key Assumptions Check）
3. 悪魔の代弁者 / 反対思考
4. 確からしさ（likelihood）の固定語彙
5. 確信度（confidence）の表現
6. 事実・推論・憶測の3段階タグ

---

## 1. 競合仮説分析（ACH, Richards Heuer）

**核心**: 「最も支持される仮説」を選ぶのではなく、「**最も矛盾（反証）の少ない仮説**」を選ぶ。仮説を支持する証拠ではなく、**反証しうる証拠**で評価する。これが確証バイアスへの直接的対抗策。

**手順（lite版）**:
1. **複数仮説を立てる**: 3つ以上。最初に思いついた答えに飛びつかない（真の答えが選択肢から漏れるのを防ぐ）。
2. **証拠×仮説の表を作る**: 各証拠が各仮説と整合するか/矛盾するかを記入する。
3. **診断力（diagnosticity）を見る**: ある証拠が複数の仮説と等しく整合するなら、それは仮説を**区別しない**＝価値が低い。仮説を区別する証拠に注目する。
4. **最も矛盾の少ない仮説を選ぶ**: 支持証拠の多さではなく、反証の少なさで選ぶ。
5. **感度分析**: 鍵となる証拠が誤り/欺瞞だったら結論はどう変わるかを確認。
6. **却下した仮説も報告する**: なぜ他の仮説を退けたかを書く。

**注意（正直な但し書き）**: ACHの完全な儀式的マトリクスがバイアスを測定可能なほど減らすかは、学術的には賛否両論（Dhami et al. 2019 はブレインストーミングと悪魔の代弁者には実証的支持があるがACHには乏しいとする）。**価値の核は「反証を探す」原則**にあるので、表の形式に過度に依存せず、反証志向そのものを重視する。

## 2. 重要前提のチェック（Key Assumptions Check）

結論を支える前提を明示的に列挙し、各前提について問う：
- これにどれくらい自信があるか？
- これが間違っていたら、結論はどう壊れるか？
- かつては正しかったが、今はもう成り立たないのではないか？

最も多い静かな失敗は、「当然の前提」が実は間違っていることなので、それを表に出す。

---

## 3. 悪魔の代弁者 / 反対思考（Consider-the-Opposite）

結論を確定する前に、その結論が**間違っている最強の理由**を明示的に書き出す。

なぜ有効か: 「客観的であれ」「公平であれ」という指示単独より、**構造化された反対生成**のほうが過信・アンカリングの是正効果が高い（Lord, Lepper & Preston 1984）。悪魔の代弁者・弁証法的探求は、合意ベースの意思決定より質の高い結論を生むことが複数研究で確認されている。

ただし、反対思考は「判断の校正」には効くが「情報収集段階の確証バイアス（選択的接触）」は単独では直しにくい（2023年の登録研究）。だから**収集フェーズの反証クエリ**（SKILL.md フェーズ2）と**併用**することが重要。

## 4. 確からしさ（likelihood）の固定語彙

予測・推定には固定語彙を使い、読み手が「可能性が高い」の意味を推測せずに済むようにする。下記いずれかを採用し、使った%帯を記録する。

**ICD 203（米国IC標準）**
| 語 | 確率帯 |
|----|--------|
| ほぼ可能性なし (almost no chance) | 01–05% |
| 非常に低い (very unlikely) | 05–20% |
| 低い (unlikely) | 20–45% |
| ほぼ五分 (roughly even chance) | 45–55% |
| 高い (likely) | 55–80% |
| 非常に高い (very likely) | 80–95% |
| ほぼ確実 (almost certain) | 95–99% |

**英国PHIA Probability Yardstick** も同様の7段階（remote chance ≤5% / highly unlikely 10–20% / unlikely 25–35% / realistic possibility 40–<50% / likely 55–75% / highly likely 80–90% / almost certain 95–<100%）。

---

## 5. 確信度（confidence）の表現

**確からしさ（likelihood）と確信度（confidence）を同じ文に混ぜない**。これはICD 203とPHIAが明確に定めるルール。

- **確からしさ**: その事象/主張が真である**確率**。
- **確信度**: その確からしさ判断が立つ**土台の堅さ**（情報源の量・質・裏付けの強さ・空白の有無に基づく）。high / 中 / 低 で示す。

例（良い）：「価格は今四半期に上昇する可能性が高い（likelihood）。情報源が一次統計2件で一致しており確信度は高い（confidence）。」
例（悪い）：likelihoodとconfidenceを1つの曖昧な「たぶん高確率で確実」に融合させる。

なぜ重要か: 強そうに聞こえる確率が、弱い証拠を覆い隠すのを防ぐ。LLMは言語化した確信度を系統的に過信するため、複数サンプルの一致度で校正し、低ければヘッジ表現を使う。

## 6. 事実・推論・憶測の3段階タグ

報告の各主張に必ず付ける（「正しさ」と「出典が支持していること」は別軸）：

- **[事実]** = 引用した独立ソースが実際にその文を支持している（AIS基準: 一般的な読者が「その出典によればXだ」と同意できる）。裏取り済み。
- **[推論]** = 事実から自分が導いた解釈。推論であると明示。
- **[未確認/憶測]** = もっともらしいが出典の裏付けがない。明示的にそう書く。事実として混ぜない。

主張が事実として正しくても、引用元が支持していなければ「事実」ではなく「推論」か「未確認」。これが引用忠実性（faithfulness）の考え方。
